# The labs design system

This is the system for the **chrome**: everything around the figure that a learner reads, presses,
or is told by. The figure itself has its own rulebook (`.claude/skills/lab-design/SKILL.md`, "Art
direction"); the two share one voice but answer different questions. This document answers: why
does a lab look and behave the way it does, and how do I build one that fits.

The short version. A lab is one calm container with a figure as its hero. Everything else is
quiet, aligned to one scale, and appears when it earns its place. Colour is spent on meaning (what
is picked, what is right, what changed), never on decoration. Motion tells the learner what caused
what. Every size, weight, gap, tint and duration comes from a token, so 274 labs read as one product.

## 1. Where the system sits

```
host theme (shadcn)     --primary, --card, --border, --radius …   the app decides the look
        │ bound by
lab semantic tokens     --lab-accent, --lab-surface, --lab-good …   one name per meaning
        │ used by
lab scales + roles      --lab-sp-*, --lab-t-*, --lab-w-*, --lab-dur-* … one value per step
        │ used by
lab components          .lab-choice, .lab-readout, .lab-segmented …  one class per part
        │ composed by
Activity.*              Root / Header / Status / Canvas / Dock / Inspector / Feedback / Transport
```

Two consequences. First, labs never choose a colour: they choose a **meaning** (`accent`, `good`,
`warn`, `danger`, `muted`) and the host's theme decides the hue, in light and dark. Second, labs
never choose a **number**: they choose a step. `tests/css-scale.test.ts` and `tests/css-system.test.ts`
fail the build on a raw value, so the system cannot quietly drift back into taste.

The token source of truth is the `:root` block at the top of `styles/core.css`. `design-tokens.json`
is exported from it in the W3C Design Tokens format (DTCG 2025.10) for design tools; run
`node scripts/export-tokens.mjs` after changing a token, and `labs:check` fails if it is stale.

### What a consumer imports

```css
@import '@classytic/labs/styles/core.css'; /* tokens, shell, components  (~104 KiB) */
@import '@classytic/labs/styles/figure.css'; /* figure art direction        (~9 KiB)  */
@import '@classytic/labs/styles/domains/math.css'; /* ONE subject               (~29 KiB)  */
```

`styles.css` pulls in everything, which is right for a gallery and wrong for a course page: the
domain sheets are split per subject precisely so a maths page does not download physics, chemistry
and language. `styles/domains.css` is the whole set in its original order for anyone who does want
it all. The split is generated by `scripts/split-domains.mjs`, which cuts at rule boundaries into
contiguous slices, so concatenating the parts reproduces the original file byte for byte: the
cascade cannot have moved. Budgets are enforced per subject (40 KiB), not in aggregate.

## 2. Tokens

### Colour (semantic, host-bound)

| Token                                        | Meaning                                                             | Host binding                                |
| -------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------- |
| `--lab-surface` / `--lab-sunken`             | the card / a recessed band (dock, sunken input)                     | `--card` / `--muted`                        |
| `--lab-fg` / `--lab-muted`                   | text / secondary text                                               | `--foreground` / `--muted-foreground`       |
| `--lab-border` / `--lab-border-strong`       | hairlines / control edges                                           | `--border`                                  |
| `--lab-accent`                               | the one hue that means "this, now": picked, current, primary action | `--primary`                                 |
| `--lab-good` / `--lab-warn` / `--lab-danger` | right / caution / wrong                                             | `--success` / `--warning` / `--destructive` |
| `--lab-ring`                                 | keyboard focus                                                      | `--ring`                                    |

**State tints** are the only way a surface reacts, so "picked" is the same tint on an answer, a chip
and a segment, and "right" is one green rather than twenty:

| Token                                    | Mix                    | Used for                            |
| ---------------------------------------- | ---------------------- | ----------------------------------- |
| `--lab-accent-faint`                     | accent 5%              | hover                               |
| `--lab-accent-soft`                      | accent 12%             | picked / current                    |
| `--lab-accent-edge`                      | accent 45% into border | hover border                        |
| `--lab-good-soft` / `--lab-good-ink`     | 14% / 80%              | a right answer's surface / its text |
| `--lab-warn-soft` / `--lab-warn-ink`     | 16% / 85%              | caution surface / text              |
| `--lab-danger-soft` / `--lab-danger-ink` | 12% / 80%              | a wrong answer's surface / its text |
| `--lab-hairline`                         | border 60%             | dividers between rows               |

The mixes go toward `--lab-surface`, not transparent, so the result is the same colour on a card and
on the dock. The `-ink` variants keep text on a tint at or above 4.5:1 in both themes.

### Space: a 2px grid whose name is its value

`--lab-sp-2 … --lab-sp-32` (2, 4, 6, 8, 10, 12, 14, 16, 20, 24, 32). The number in the name is the
pixel value, so a gap can be sized by eye and an author cannot invent 0.35rem by accident. Inside a
component the rhythm is 4 / 8 / 12; between regions of the shell it is 12 / 16; 24 and 32 separate
sections that must read as separate.

### Type: seven sizes, four weights, four leadings

| Role    | Size                 | Weight       | Leading    | Tracking       | Where                                            |
| ------- | -------------------- | ------------ | ---------- | -------------- | ------------------------------------------------ |
| title   | `--lab-t-title` 20   | bold 750     | title 1.25 |                | the lab's one heading                            |
| hero    | `--lab-t-hero` 24    | bold         | tight 1    | tight −0.015em | a headline value in a Readout                    |
| lead    | `--lab-t-sm` 14      | medium 550   | ui 1.45    |                | **the step's question**, the most important line |
| body    | `--lab-t-body` 16    | regular 450  | prose 1.55 |                | explanations, OBSERVE, descriptions              |
| ui      | `--lab-t-sm` 14      | semibold 650 | ui 1.45    |                | control text, stat labels, answers               |
| eyebrow | `--lab-t-eyebrow` 12 | bold         | ui         | caps 0.06em    | section labels, uppercase only                   |
| micro   | `--lab-t-micro` 10   | semibold     | tight      |                | figure annotations, the answer letter            |

The lead is body-coloured and medium weight on purpose: it is the question the learner is answering,
and muted 13px fine print for it was the single most common hierarchy bug in the old labs. Answers
sit one step **below** the question (14/450) so the block reads top-down. Numbers that change use
`font-variant-numeric: tabular-nums` so a value can tick without the layout shifting.

### Radius, elevation, layering

`--lab-r-xs` 4 (chips, the answer letter), `--lab-r-sm` 8 (controls), `--lab-r-md` 12 (answers,
inspectors), `--lab-r-lg` 16 (the activity root), `--lab-r-pill` for tracks and pills. Shadows are
`--lab-shadow-sm|md|lg` and appear only on the one container and on a hovered answer; inside the
container, regions are separated by hairlines, never by shadows. `--lab-z-raised|overlay|top` are
the only three layers.

### Targets

`--lab-target` 44px for anything the learner **commits** with: answers, the primary action, transport,
the hit area of a slider. `--lab-target-compact` 36px for dense secondary controls inside the dock
(chips, segments, icon buttons). Both clear WCAG 2.2 AA's 24px minimum with 8px between targets;
44 follows Apple's HIG and the touch research behind it for the actions that matter.

### Motion

Three durations, three curves, one rule for who uses which:

| Token               | Value                 | Cause                                                                   |
| ------------------- | --------------------- | ----------------------------------------------------------------------- |
| `--lab-dur-fast`    | 120ms                 | the **pointer** caused it: hover, press, focus                          |
| `--lab-dur-base`    | 180ms                 | the **model** caused it: a value lands, a chip lights, a state resolves |
| `--lab-dur-slow`    | 260ms                 | something moves **through space**: a node slides, a panel opens         |
| `--lab-ease`        | (0.2, 0.8, 0.2, 1)    | decelerating: things arrive                                             |
| `--lab-ease-in-out` | (0.4, 0, 0.2, 1)      | things move between two places                                          |
| `--lab-ease-spring` | (0.34, 1.56, 0.64, 1) | one landing pop; sparingly                                              |

Exits run at `fast`. Only `transform` and `opacity` animate for movement. Anything longer than
`slow` is scene physics (a wave, a current) and is authored in the scene with its own duration.
`prefers-reduced-motion` is honoured **once**, at the package root: every transition and animation
collapses to 10µs and confetti is removed. A scene that must move to teach (a flowing current) keeps
a static state that still shows the fact.

### Focus

One ring: `outline: var(--lab-focus-ring); outline-offset: var(--lab-focus-offset)` (2px of the
host's ring colour, offset so it never covers the control's own border), applied by a single shared
`:focus-visible` rule to every focusable element under a lab root. A component overrides it only
when the focused thing is SVG geometry with no box to outline (a tree node's halo, a pin), and then
it draws the same colour at the same weight. Focus is never removed, only relocated.

## 3. The learning grammar, and the chrome that carries it

The shell is not a layout; it is an argument. Each region exists because a finding about how people
learn says it should, and each principle has exactly one home so it is never said twice.

| Region                                             | Carries                                   | Why (the finding)                                                                                                                                                                                                                       |
| -------------------------------------------------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Predict gate** (`PredictGate`, `.lab-challenge`) | the learner commits before seeing         | Generation and retrieval effects: a prediction that is then contradicted or confirmed is remembered; watching is not. The figure is unmounted, not blurred, so the answer cannot leak. Committing, right _or_ wrong, unlocks the model. |
| **Step lead** (`.lab-authored-task-lead`)          | the one question for this step            | Segmenting (Mayer): one idea per step, learner-paced. The lead is the most important sentence on screen and is styled as such.                                                                                                          |
| **Figure** (`Activity.Canvas`)                     | the phenomenon                            | The figure is the hero: ≥ 55% of the height above the fold. A lab that is mostly chrome is a document, not an instrument.                                                                                                               |
| **Status strip**                                   | 1–3 live parameters                       | Signalling: the values that explain the figure sit on it, in the only tinted band, so the eye finds them. Never a sentence.                                                                                                             |
| **Readout / StatList**                             | the headline number, then supporting ones | Spatial contiguity: the measurement sits with the thing measured, not in a sidebar. A value that changes flashes once (`.lab-val-flash`) so the learner sees cause → effect.                                                            |
| **OBSERVE** (`Activity.Feedback`)                  | one sentence of interpretation            | Coherence: the interpretation, not a paragraph. Directly under the figure, with a 3px accent rule, not a box.                                                                                                                           |
| **Answer states**                                  | picked / right / wrong, with a note       | Feedback is immediate on a _prediction_ (the point is to contradict a prior) and the wrong state carries the misconception note (`⚠`), never just red: colour alone is not feedback.                                                    |
| **Inspector** (`<details>`)                        | evidence, hints, transcript               | Progressive disclosure: explanation appears when asked for, so the figure is not shrunk by text the learner has not earned yet.                                                                                                         |
| **Transport**                                      | back · n / N · continue                   | Multi-step flows show where you are and always allow back; the primary action never moves.                                                                                                                                              |

Two deliberate asymmetries follow from the research on desirable difficulties: feedback is
**immediate** at a predict gate (the learner needs the contradiction while the prior is live) but
**withheld** on a transfer question until the learner commits, and hints are behind a disclosure
rather than shown, because an always-visible hint makes performance depend on the prompt.

## 4. Components

Every interactive part shares one **state vocabulary**, expressed as data attributes the CSS reads:

| State            | Attribute                                         | Look                                                                        |
| ---------------- | ------------------------------------------------- | --------------------------------------------------------------------------- |
| idle             |                                                   | surface, `--lab-border`, ui text                                            |
| hover            | `:hover`                                          | `--lab-accent-faint`, `--lab-accent-edge` border, no shadow on list answers |
| focus            | `:focus-visible`                                  | the shared ring                                                             |
| picked / current | `data-picked`, `data-state="sel"`, `aria-pressed` | `--lab-accent-soft`, accent border, medium weight                           |
| right            | `data-tone="correct"`, `data-state="ok"`          | `--lab-good-soft`, `--lab-good-ink` text, cursor default                    |
| wrong            | `data-tone="wrong"`, `data-state="no"`            | `--lab-danger-soft`, `--lab-danger-ink` text, one 260ms shake               |
| disabled         | `:disabled`                                       | 50% opacity, default cursor, no hover                                       |

| Part          | Class                              | Notes                                                          |
| ------------- | ---------------------------------- | -------------------------------------------------------------- |
| answer, long  | `.lab-challenge-q .lab-choice`     | one per row, lettered handle, 14/450, quiet border             |
| answer, short | `[data-response-layout="compact"]` | a 3-column grid for tokens like "42" / "True"; keep sets to 3  |
| mode toggle   | `.lab-segmented` + `.lab-segment`  | 2–4 mutually exclusive modes, one track; never stacked buttons |
| chip          | `.lab-chip`                        | a toggle or a legend entry; `--lab-target-compact`             |
| field         | `.lab-field` + `.lab-field-label`  | eyebrow label above, value at the end, ≤ 3-word label          |
| readout       | `.lab-readout`                     | eyebrow · hero value · ≤ 8-word sub                            |
| stat list     | `.lab-statlist` / `.lab-stat`      | label … value rows, hairlines between, tabular numerals        |
| status pill   | `.lab-pill`                        | one word of state, tinted by tone                              |
| callout       | `.lab-activity-feedback`           | eyebrow + one sentence, 3px accent rule, no box                |
| transport     | `.lab-activity-transport`          | back / progress / primary, `--lab-target` tall                 |

## 5. Rules that keep it whole

1. One bordered container per lab. Inside it, hairlines.
2. A number is a token. A colour is a meaning. A weight is a role.
3. The step lead is the heaviest text after the title; answers sit one step below it.
4. Colour carries meaning, so it is rare: picked, right, wrong, current, and the accent rule.
5. Motion explains cause: pointer → fast, model → base, movement → slow. Nothing decorates.
6. Every focusable thing shows the ring. Every commit target is 44px.
7. Say it once. A live fact has one home (status, readout, OBSERVE, transcript).
8. Nothing is hidden by `aria-hidden` that a learner still needs to see; nothing that a learner
   cannot reach is left in the layout (collapsed panels really collapse).
9. Rasterize light **and** dark before calling it done; run `collisions:check` and
   `overflow-check` because the eye misses what the browser measures.

## 6. Sources

The principles above rest on: Mayer's multimedia learning principles (coherence, signalling,
segmenting, spatial and temporal contiguity); Bjork's desirable difficulties and the retrieval and
generation effects (immediate feedback for predictions, withheld feedback for transfer); WCAG 2.2
(2.5.8 target size minimum 24px, 2.4.11 focus not obscured, 2.4.13 focus appearance); Apple HIG and
Material motion guidance (150–300ms micro-interactions, transform/opacity only, reduced motion);
and the W3C Design Tokens Community Group format 2025.10 for the exported token file.
